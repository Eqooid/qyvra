# Account settings and real Phase 1 browser verification

## Account settings

`/settings` is protected by the existing authenticated layout and is linked from
the account menu. Profile editing supports only display name, timezone and locale.
It uses the existing current-user query and `PATCH /api/v1/me`, updates the header
immediately, and preserves input after recoverable errors.

Password changes use `PATCH /api/v1/me/password`. Confirmation is checked locally
and is never sent. The server's configurable password policy remains authoritative.
The current session survives; other sessions are revoked. Password inputs are
cleared after success. Incorrect-current-password responses are not automatically
retried as password writes and do not sign out an otherwise valid session.

The confirmation dialog for `POST /api/v1/auth/logout-all` revokes sessions on the
server, clears protected query data and redirects to login. No backend contracts,
database migrations, credentials or production environment settings were changed.

## Isolated real-browser environment

Requirements: Node 24, the installed web dependencies, Docker Desktop running
Linux containers, and Chromium installed once with:

```sh
cd apps/web
npx playwright install chromium
cd ../..
```

From the repository root, the canonical verification command builds/starts the
existing Compose application, runs Chromium through Nginx, and stops the isolated
stack in a finally block without deleting volumes:

```sh
npm --prefix apps/web run test:e2e
npm --prefix apps/web run test:e2e:headed
```

The explicit project is `brainless-e2e`, with separate `postgres_data` and
`storage_data` volumes. The public URL is **http://localhost:18080**. A generated
database password is stored only in ignored `.tools/brainless-e2e.env`. Normal
development `.env` and volumes are not used. Authentication uses random opaque
sessions; the application does not require an additional session-signing secret.

The small override uses a 2 MiB upload limit and longer test rate-limit budgets.
Expiry verification temporarily recreates only the isolated API with eight-second
access and refresh lifetimes through normal validated configuration, then restores
the usual test configuration. Tests must not run concurrently against this project.

For targeted work using existing images, without another build:

```sh
docker compose -p brainless-e2e --env-file .tools/brainless-e2e.env -f docker-compose.yml -f infrastructure/e2e/compose.yml up -d --wait
cd apps/web
npx playwright test phase-one.spec.ts
cd ../..
node infrastructure/e2e/run.cjs validate
node infrastructure/e2e/run.cjs logs
node infrastructure/e2e/run.cjs down
```

The environment file is generated by the first canonical run. Alternatively,
`node infrastructure/e2e/run.cjs up` generates it and builds/starts the stack.
For debugging, run `npx playwright test --debug` from `apps/web` with this stack
already running. Stop it afterward with the documented `down` command.

## Evidence and artifact policy

Tests use normal forms and real cookie-authenticated requests, generated PNG files,
and unique synthetic accounts. API calls are not intercepted. Direct authenticated
API requests are limited to authorization/session assertions. Downloads are compared
by SHA-256. Container recreation retains database records and matching file bytes.
Cancellation throttles a real Chromium connection, aborts through the UI, and checks
that no document appears and the isolated storage file count returns to its baseline.

`apps/web/playwright-report/results.json` records results. The reporter redacts
generated test passwords. Failed main-workflow screenshots mask password inputs.
Network traces and videos are disabled because they can capture passwords/cookies.
Generated reports, test results and environment files are ignored and excluded from
production images. No test performs a database reset or volume deletion.

**Destructive, optional cleanup:** only after inspecting the project name, this
removes the isolated test database and uploaded fixtures, never normal Brainless data:

```sh
docker compose -p brainless-e2e --env-file .tools/brainless-e2e.env -f docker-compose.yml -f infrastructure/e2e/compose.yml down --volumes
```
