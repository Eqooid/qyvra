# Qyvra v1.3.1 — Local AI Provider Compatibility

Prepared **13 October 2026**. **CONDITIONALLY READY**, based on the actual
[T05 verification](../local-provider-verification.md). This is an unpublished
candidate, not a release announcement. `VERSION` records product candidate `1.3.1`;
no commit, tag, push or deployment is performed by T06.

## Included

- T07 patches Next.js and matching ESLint configuration to 16.3.8 to resolve the
  reproduced production-audit gate, and extends encrypted PDF byte checks.
  [Candidate review and exact proposed commit scope](../local-provider-release-candidate-review.md)
  records the failed baseline CI run and pending final-candidate remote verification.
- Native Ollama embedding and generation adapters behind the existing independent
  interfaces; OpenAI-compatible HTTP adapters remain supported.
- Pinned model digest and tokenizer checks, bounded input/context/output, validated
  embedding vectors and structured generation responses.
- Shared API/worker configuration, optional read-only assets and Docker host access.
- Real Nomic/Qwen PDF-to-RAG/browser verification, profile isolation, SQL authorization,
  citation validation, checkpoint recovery and real Qdrant rebuild.
- Isolated verification tools and PDF fixture byte protection for Windows checkouts.

No new database migration, public AI API format, frontend redesign, provider SDK,
agent framework or separate job system. PostgreSQL is authoritative; RabbitMQ
transport, Redis progress and Qdrant derived index retain their existing roles.
Elasticsearch is still Planned, not an installed v1.3.1 service.

## Compatibility and evidence

The certified deployment uses host Ollama **0.40.3**, Docker Desktop Linux engine
**27.4.0**, `nomic-embed-text:v1.5` (768 dimensions) and `qwen3:0.6b` with thinking
disabled, 4096 context and 256 output tokens. Exact model digests and tokenizer
revisions/hashes are in the [setup guide](../development/local-ai.md#verified-assets).
Other model names are configurable; this is not certification of every Qwen model.

All four cloud/local combinations pass deterministic configuration/factory checks.
Only Ollama/Ollama has the recorded real-model application E2E; paid OpenAI smoke
tests were not run. T05 retains 91 API unit, 39 SQL, 12 frontend and 9 configuration
checks, adds a tenth live network check, 36 real-service integration cases and seven
PDF byte checks. Counts belong to separate runs/levels; filtered cases are not new
passes. Actual workflow verifies PDF extraction, durable native embeddings, READY
activation, owned retrieval, grounded citations and browser source navigation.

## Upgrade from v1.3.0

1. Back up PostgreSQL and original files, retain volume mappings and the exact previous
   code/images/configuration. Review the complete v1.3.1 working tree before publishing.
2. Build matching API/worker/outbox from the reviewed candidate. Private package
   versions stay `0.0.1`; OpenAPI `1`, `/api/v1` and transport/profile versions stay unchanged.
3. The migration chain remains the same 15 migrations. Apply pending existing migrations
   through normal startup; this increment does not add a new migration or require a reset.
4. OpenAI-only deployments keep their existing profiles/endpoints. Enabled official
   OpenAI operations now require their own nonempty API key and HTTPS at startup.
   Disabled operations and native Ollama do not require a real OpenAI key.
5. To opt into local AI, prepare installed models and pinned bundles using
   [the reproducible setup](../development/local-ai.md). Seed the immutable SQL profile
   before enabling ingestion; mount assets read-only and configure API/worker together.
6. Changing embeddings requires new compatible checkpoints/indexes. Follow the
   [staged profile cutover](../developer/versions/v1.3.1.md#profiles-indexing-and-cutover).
   Do not reinterpret cloud vectors as local vectors. Generation-only changes do not
   require document reprocessing.
7. Rebuild/restart only affected services; verify owned status, retrieval and citations
   with synthetic content before adopting the configuration for private documents.

Use documented Compose commands and existing reprocess/backfill facilities, not a
new migration/reindex CLI. Avoid `down -v`, shared collection deletion and model downloads
inside normal startup. The isolated T05 runner is test tooling, not production deployment.

## Rollback considerations

Restore the previous API/worker/outbox code/images and configuration together. With
no new schema migration in this increment, a migration-down operation is unnecessary.
The previous OpenAI profile and its valid embeddings must still exist; restore SQL
serving selection plus the matching API endpoint/assets/fingerprint and worker
configuration. Generation-only rollback does not invalidate embeddings.

v1.3.0 has no native Ollama adapter, so leaving native fingerprints/endpoints enabled
after rolling back is unsafe. Pause local enrollment before switching, account for
queued/in-progress native jobs and verify bounded recovery under the restored config.
Retain old vectors/checkpoints until validation completes. If old derived indexes
were cleaned, rebuild them from compatible durable embeddings with the appropriate
version's existing processing operations. Do not claim an automatic tested rollback
or delete new profiles to force it; downgrade to a separate compatible backup if
necessary. T05 did not execute a complete production rollback.

## Known limits and release gate

- CONDITIONALLY READY for the documented pair and host Docker Desktop networking.
  CPU-only, other GPU/LAN/remote TLS deployments and model templates require validation.
- Bundles are operator-provisioned data; digest, template, token counts and context
  must match. No bundled model weights, automatic downloading or model-management UI.
- Test score calibration is for synthetic facts, not a production similarity default.
- Small Qwen can produce invalid output on adversarial context. The server safely
  rejects it; citations do not prove all factual claims or universal injection resistance.
- Separate tenants, OCR, new formats, chat persistence, streaming, agents, MCP/Hermes,
  LangChain/LangGraph, GPU management and hybrid search are excluded.
- Remote CI, paid-provider inference and exhaustive live process termination at every
  stage were not repeated. Retained deterministic evidence is clearly distinguished
  from new live verification. No unresolved release-blocking defect was observed.
