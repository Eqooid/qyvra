# Brainless v1.1.0 release snapshot

- Phase: **Phase 2 — document organization and metadata**
- Acceptance date: **2026-09-25**
- Git tag: **v1.1.0**, locally verified at `f55dacf9bb5faecbf54460ce1daf3d4d6ebaf102` (remote release publication not checked)
- Release decision: **READY FOR v1.1.0 RELEASE**; no unresolved release blocker
  was found in final acceptance.

Brainless v1.1.0 lets an owner describe documents, see the current file directly
in the catalog, and narrow and order the catalog by metadata without opening each
document. PostgreSQL remains the metadata source of truth; private file storage,
ownership and the Phase 1 document lifecycle remain in place.

## Included

- A nullable owner-entered description on upload and document PATCH, including
  explicit `null` clearing and read/display/edit support. Uploads omitting it remain
  valid. Existing completed upload receipts replay in their original shape.
- A safe, nullable `currentVersion` summary on document list, detail and PATCH
  responses, with filename, MIME, size, version number and upload timestamp.
- Database-side current-filename/MIME, all-of tag and UTC calendar-day
  created/updated filters. Existing metadata/category/status/archive filters still
  combine with them. The web catalog exposes the new controls and active filters.
- An explicit document sort allow-list, stable UUID tie-breakers, validated opaque
  keyset cursors and Next/Previous web navigation. Changing filters or order
  starts a new cursor traversal.

The [API contract](../api.md#v110-document-contract), [database guide](../database.md#v110-description-migration-and-query-design),

## Upgrade and compatibility

Apply checked-in Prisma migrations before starting the updated API. Migration
`20260924010000_document_description` adds nullable `documents.description` with
a bounded-text CHECK; it does not rewrite existing rows, versions or upload
receipts. The rollback is intentionally forward-only because dropping the new
column would lose descriptions entered after upgrade. Existing Phase 1 upload
clients may continue omitting description. Document-list clients retain the
existing envelope, cursor metadata and default sort; new fields are additive.

Private npm manifests remain at `0.0.1` and generated OpenAPI at `1` under the
[versioning policy](../development/conventions.md#versioning); the product release
is designated by the `v1.1.0` Git tag. See the
[developer delta and upgrade guide](../developer/versions/v1.1.0.md) for the
comparison baseline, source walkthroughs and compatibility details.

## Acceptance evidence

- The Phase 1-to-v1.1.0 migration upgrade and constraint tests passed in an
  isolated PostgreSQL database during focused integration verification.
- That verification recorded 52 PostgreSQL API integration tests, 91 HTTP
  contract tests, 30 document unit tests and 106 focused frontend tests passing.
  API/web type checks, targeted lint/format checks and API build passed.
- A complete six-test Chromium workflow passed through isolated Docker Compose
  and Nginx on 25 September 2026. It used the real Next.js, NestJS and PostgreSQL
  stack and covered upload/description, current-version and history, filters,
  sorting, cursor traversal, ownership and relevant Phase 1 regressions.
- The Docker web production image built successfully for that browser run.
  Final acceptance repeated two document unit suites (11 tests), the document HTTP
  suite (70 tests), and six affected frontend suites (100 tests); all passed.
  API/web type checks and lint, Prisma schema validation and the API production
  build also passed. No runtime source changed after the browser run.

The [test guide](../development/testing.md#real-browsers-through-nginx) describes
the repeatable browser command and isolated project. The browser evidence is
Chromium coverage, not cross-browser or physical-device certification.

## Deferred

Processing/OCR, Redis and RabbitMQ workflows, Elasticsearch, Qdrant, embeddings,
LLM providers, RAG and agents are later-phase work. Custom metadata, historical
file download/promotion, Trash and permanent purge, exact catalog totals and
deployment CI are also outside v1.1.0. No future search or AI service is required
to run this release.
