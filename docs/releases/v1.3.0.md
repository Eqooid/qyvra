# QYVRA v1.3.0 — Phase 4 release-candidate snapshot

- Phase: **Phase 4 — AI/RAG foundation, implementation and local verification complete**.
- Prepared: **8 October 2026**; this is not a publication date.
- Readiness: **READY WITH KNOWN NON-BLOCKING LIMITATIONS**, based on [T12](../phase-4-verification.md).
- Git: existing `v1.3.0` branch; **no v1.3.0 tag, immutable release commit or publication** at preparation.
- Release notes: this snapshot; [changelog](../../CHANGELOG.md) records technical changes.
- Finalization evidence and recommended Git steps: [T13 preparation record](../phase-4-release-preparation.md).

Qyvra can now extract text from supported PDFs in the background, search an owner's
indexed documents by meaning, and answer standalone questions with validated
citations. Citation navigation opens the exact retained document/version/chunk
source. AI processing is opt-in; ordinary document access remains available when
AI services fail. This is a retrieval and Q&A foundation, without an agent runtime.

## Included

- Bounded, isolated PDF.js extraction with canonical persisted text, content hashes,
  extractor identity and truthful page provenance. Image-only PDFs require future
  OCR; encrypted/malformed/limit-exceeding PDFs produce controlled failures.
- Deterministic, token-bounded chunking with stable UUIDv5 chunk identity, ordering,
  overlap, Unicode scalar offsets and citation-ready page spans.
- Qyvra-owned embedding interfaces and a native OpenAI-compatible HTTP adapter;
  immutable model/profile identity and PostgreSQL batch checkpoints permit resumption.
- Private, profile-isolated Qdrant collections, repeatable point upserts, verified
  activation, generation replacement and durable lifecycle cleanup/reconciliation.
- Opt-in upload/new-version enrollment, owned idempotent reprocessing, restore
  artifact reuse and bounded dry-run/apply/resumable maintenance backfill.
- Authorized semantic search using compatible query embeddings and mandatory owner,
  profile and ready-manifest filters, followed by canonical PostgreSQL validation.
- Bounded standalone RAG using a separately configured generation HTTP adapter,
  insufficient-evidence responses and server-validated claim/citation references.
- Authenticated AI Search/Q&A, processing readiness, safe plain-text answers and
  authorized source navigation, including retained historical text provenance.

## Authority and security

PostgreSQL owns business state, ownership, jobs, canonical text/chunks, embedding
checkpoints and activation pointers. Stored files remain authoritative originals.
RabbitMQ carries identifiers, Redis provides disposable progress and Qdrant is a
rebuildable derived index. The API owns authorization/retrieval/RAG; the existing
dedicated worker performs integrity, extraction, chunking, embeddings and indexing.
No independent AI job system is introduced.

The session's internal user ID determines ownership; there is no separate tenant
entity in this release. Qdrant payloads cannot grant access. Canonical sources are
checked before provider disclosure and again before publication. Archive/soft delete
exclude content immediately, even when remote deletion is delayed. Source routes
enforce document/version/chunk ownership and lifecycle rather than trusting links.

Document text is untrusted evidence, separated from application instructions.
Models cannot execute tools or create authoritative citations. Citation tokens must
map to server-supplied SQL provenance; prompt wording alone does not guarantee
injection resistance or factual correctness. Provider keys remain server-side;
production Qdrant has no public port or Nginx route.

## Upgrade and configuration

Back up PostgreSQL and private originals, preserve existing volume mappings and
use version-matched API/worker/outbox images. The complete checked-in chain has
**15 migrations**. Phase 4 adds `20261004010000_ai_data_foundation` and
`20261006010000_ai_reprocessing_requests`; historical migrations are unchanged.
Migrations create no AI profiles, run backfill or call providers. These statements
describe the tested SQL upgrade, not an unexecuted old-release Docker upgrade.

From a new checkout only, copy `.env.example` to `.env` and replace placeholders.
Preserve an existing `.env`; do not copy over deployment credentials.

```sh
docker compose config --quiet
docker compose up --build -d
docker compose ps --all
docker compose logs --tail 100 migrate api worker outbox
```

The one-shot migration service must exit 0 before API/worker startup. Open
`http://localhost:8080`; the default Compose stack is local HTTP, not a complete
public production deployment. Production requires the documented TLS, secure-cookie,
origin, private-service, backup and provider privacy controls.

AI defaults remain disabled. Provision an immutable SQL embedding profile and the
serving selection before enabling ingestion/query features. Align profile fingerprints,
chunk settings, dimensions/model revisions and worker/API configuration. Configure
generation independently. Calibrate the retrieval score threshold before enabling
RAG. No universal score threshold or automatic profile-provisioning CLI is claimed.

See [deployment/configuration](../compose.md), [environment settings](../deployment/environment-variables.md),
[embedding configuration](../phase-4-embedding-generation.md#configuration-and-deployment),
[ingestion configuration](../phase-4-ingestion.md#configuration-and-deployment),
[search configuration](../phase-4-semantic-search.md#configuration-and-deployment) and
[generation configuration](../phase-4-rag-answers.md#configuration).

Existing versions are enrolled through explicit bounded backfill, not migration
side effects. Start with the implemented dry-run:

```sh
docker compose exec api node /app/infrastructure/docker/database-command.cjs node scripts/ai-backfill.cjs --batch 25 --max 100
```

Use documented `--apply`/cursor controls after review. Qdrant loss requires explicit
index-only reprocessing or the trusted rebuild boundary; ordinary backfill trusts
SQL readiness and does not detect missing remote collections. Valid durable
embeddings rebuild Qdrant without new document embedding calls. Redis loss, broker
interruption, worker crashes and provider outages have distinct
[tested recovery procedures](../phase-4-verification.md#operational-recovery).
Never delete authoritative volumes or manually mark stages complete as a repair.

Rollback is an operator-reviewed restore of compatible images and, where necessary,
matching database/file backups. Do not drop derived tables containing retained
provenance or run migration reset against deployment data. Mixed-version rollout,
production backup restore and rollback are **not verified by T12**.

## Verification and known limitations

T12 records builds, type/lint checks, all 15 clean migrations and a Phase 3 SQL
upgrade, retained-volume recreation and native Linux worker/container tests.
Its combined runs cover **419 API unit**, **237 API integration**, **281 API HTTP**,
**214 frontend** and **11 browser** cases. These are aggregate evidence, not one
monolithic rerun. Real PostgreSQL, RabbitMQ, Redis and Qdrant were exercised;
provider computation used deterministic doubles/HTTP fixtures, not paid/live models.

Authorization, forged vector payloads, invalid citations, no-evidence abstention,
checkpoint/lease recovery, Qdrant loss/rebuild without re-embedding, lifecycle
exclusion and Phase 1–3 regressions passed in the recorded scope. Production npm
high/critical gates passed; five moderate API findings and development-tooling
advisories remain. The full web formatting check has 25 unchanged baseline warnings.
Remote GitHub CI, live-model quality/adversarial evaluation, production capacity/HA,
comprehensive accessibility certification and a true Phase 3 Docker-volume upgrade
were not executed. Run the new workflow on the exact reviewed commit before tagging.

Only text-bearing PDFs are AI-extractable; original PDF/JPEG/PNG storage remains
supported. No OCR, additional AI document formats, persistent conversations,
streaming, hybrid retrieval, advanced reranking, external actions, autonomous agents,
multi-agent orchestration, LangChain/LangGraph, Hermes/MCP integration or local model
orchestration is delivered. The native adapters support their documented compatible
HTTP contracts, not every provider or future Ollama/local adapter. Elasticsearch
remains **Planned** and is not part of the running Phase 4 stack.

Historical source navigation displays retained canonical text, not a historical PDF
viewer/download. There is no independent tenant policy or public permanent purge.
Grounding/citation validation cannot eliminate model errors or establish semantic
entailment of every claim. Provider/model calibration, privacy terms and cost/storage
quotas remain deployment responsibilities; a crash before checkpoint commit can
repeat provider billing. See [T12's complete limitations](../phase-4-verification.md#final-blocker-and-limitation-disposition).

## Product version versus package versions

Under the [existing versioning policy](../development/conventions.md#versioning),
the product candidate is **v1.3.0**. All four private package versions remain
**0.0.1**, generated OpenAPI remains **1**, HTTP remains **/api/v1**, and message,
extractor/chunker/profile schema identities are independently versioned. Dependency
versions and lockfiles are preserved. Compose builds local images with its existing
project/service naming; no release registry image/tag or publishing automation exists.
Creating the product tag and publishing remain separate user-approved steps.
