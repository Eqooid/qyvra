# 15 · Troubleshooting

[Guide index](README.md) · [Configuration](11-configuration.md) · [Docker operations](12-docker-nginx.md)

Start by identifying the failing boundary: browser, proxy, API, database, or private storage. API errors deliberately hide infrastructure details. Use HTTP status, response request/trace ID and safe structured events; never paste cookies, database URLs, password/hash fields or private document contents into diagnostics.

| Symptom                                                | Repository-grounded explanation and next step                                                                                                                                                                                          |
| ------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Docker command reports missing Linux-engine pipe       | Docker Desktop's Linux engine is unavailable. Start/switch to Linux containers before diagnosing migration/API behavior. See [Compose runbook](../compose.md).                                                                         |
| Compose config fails before startup                    | Required POSTGRES variables are absent. Copy/edit the template while preserving existing initialization credentials and project name; run `docker compose config --quiet`.                                                             |
| API startup fails configuration validation             | Check [environment.ts](../../apps/api/src/configuration/environment.ts): required DATABASE_URL/LOCAL_STORAGE_ROOT, numeric bounds, exact Origin syntax, cookie cross-rules. Optional angle-bracket placeholders are invalid values.    |
| Host Prisma reports missing/invalid database URL       | CLI reads process DATABASE_URL; API root `.env` loading is separate. Inject the URL before `migrate:deploy`.                                                                                                                           |
| Database refuses connection or API fails startup probe | Host API needs loopback port from the dev override; container API uses postgres:5432. Check service health/port and matching credentials. Changing POSTGRES_PASSWORD does not update an initialized volume.                            |
| API is ready but feature SQL fails                     | Readiness performs SELECT 1, not schema validation. Confirm all migrations, especially receipt scope and completed-fingerprint migrations, were deployed and the generated client rebuilt.                                             |
| `migrate` container has exited                         | Exit code 0 is normal for the one-shot task. Nonzero blocks API startup; inspect `docker compose logs migrate`. Do not reset volumes to solve migration errors.                                                                        |
| Nginx is unhealthy or returns 502                      | Check API/web health, startup failures and `docker compose exec nginx nginx -t`. Internal ports are 3001/3000. `/api/` must preserve `/api/v1`; do not strip the prefix.                                                               |
| Direct host web receives HTML/404 for API calls        | Next.js has no API proxy. Set web NEXT_PUBLIC_API_BASE_URL to the host API URL ending in /api/v1. The relative default needs Nginx.                                                                                                    |
| Login/mutations return 403                             | Origin must match CORS_ORIGINS exactly; mutations need X-CSRF-Protection: 1. Same-origin login still validates Origin. A changed Nginx port also needs matching PUBLIC_APP_URL.                                                        |
| Browser blocks cross-origin requests/cookies           | Host setup needs CORS_CREDENTIALS=true and credentialed requests. Use matching hostnames; localhost and 127.0.0.1 differ. Avoid Secure cookies on local HTTP. Check cookie Path/Domain/SameSite settings and the exact allowed origin. |
| Production mode rejects local Compose settings         | Expected: production requires HTTPS origins/Secure cookies. The checked-in stack is local HTTP. Follow a deliberate TLS/forwarding deployment change rather than weakening validation.                                                 |
| Cookies exist but protected requests return 401        | The access session may be expired, revoked, replay-revoked, or linked to a deleted user. Check current session flow; a refresh cookie is not an access cookie. Login again when renewal is unavailable.                                |
| Session unexpectedly revoked after parallel refresh    | Reuse of a consumed refresh token revokes the session. Use the existing Web Lock/in-flight logic and a single canonical origin; do not add independent automatic refresh callers.                                                      |
| Access expires without auto-refresh                    | Without Web Locks, AuthApi intentionally requires login again. Ambiguous prior refresh can also suppress retries. See [auth guide](07-authentication-authorization.md).                                                                |
| Login/password requests return 429                     | Check Retry-After. Fixed-window budgets are process/socket-peer scoped; proxied users share a peer. Password change shares login/global budget.                                                                                        |
| Valid-looking upload returns 400/415                   | Check actual bytes, filename extension and browser MIME. Only PDF/JPEG/PNG are supported; encrypted/malformed PDFs and invalid/truncated images are rejected. Do not trust the extension alone.                                        |
| Upload returns 413                                     | Align file size with API limit and browser UX limit. Nginx adds 1 MiB overhead; API independently bounds file/metadata and total multipart bytes. Rebuild web after Compose limit changes.                                             |
| Upload returns 408/429                                 | Receive timed out or concurrent receive/inspection capacity is full. XHR also has its own timeout. Retry unchanged explicitly with the retained attempt key after checking the catalog.                                                |
| PDF upload returns 503 while metadata works            | qpdf may be absent/inaccessible; readiness does not inspect it. Check `qpdf --version` on host or `docker compose exec api qpdf --version`; confirm trusted UPLOAD_QPDF_PATH.                                                          |
| Upload/storage operations return 503                   | Check private root access, disk/temp capacity, symlink ancestors and hard-link support. Existing volumes may have wrong ownership; inspect deliberately instead of chmod 777.                                                          |
| Upload returns 409 after document deletion             | Checksum uniqueness includes soft-deleted/archived versions. A new key cannot bypass it. Other 409 causes include an active/conflicting key or a version target in an ineligible lifecycle state.                                      |
| Cancelled upload later appears in catalog              | Cancellation raced server completion. A stopped client request does not prove rollback. Inspect catalog/history and retry unchanged only when appropriate.                                                                             |
| Current download fails but history exists              | History describes SQL records; the current object may be missing or size-mismatched. API returns 503 rather than an older file. Use matched SQL/file backups; no automatic repair exists.                                              |
| Download logs an interruption before another request   | The UI's GET probe cancels its response body, then starts a native GET. It is not a HEAD request; two requests are expected.                                                                                                           |
| Category deletion returns 409                          | Even a soft-deleted document retains its category. Reassign/clear active documents; restore deleted ones through the API first. There is no Trash UI or automatic reassignment.                                                        |
| Data appears missing after Compose changes             | Check original Compose project name and mounts. A different namespace selects different volumes. Host private storage is separate from Compose storage. Do not delete the old volumes.                                                 |
| Frontend still uses old API URL/upload limit           | NEXT_PUBLIC settings are compiled into production web output. Rebuild/recreate web; runtime env alone cannot change existing client code.                                                                                              |
| Package import/generated Prisma types fail             | Install all four packages in the documented order and build shared packages. Do not run a nonexistent root npm install/build script.                                                                                                   |
| PowerShell blocks npm.ps1                              | Use npm.cmd for the same commands rather than changing project dependencies.                                                                                                                                                           |
| Next build cannot fetch fonts                          | Root layout uses next/font/google. Ensure required build-network access; this does not mean API runtime is broken.                                                                                                                     |
| Real DB tests fail immediately                         | TEST_DATABASE_URL is mandatory and must name a separate migrated test database. HTTP doubles are not a substitute for those tests.                                                                                                     |

Useful low-risk diagnostics:

```sh
docker compose ps --all
docker compose logs --tail 100 migrate api
docker compose logs --tail 100 nginx web
docker compose exec nginx nginx -t
```

Do not print full resolved Compose environment when sharing logs. The [configuration guide](11-configuration.md) explains which variables actually reach containers. The [storage guide](09-file-storage.md) explains why an object should not be deleted merely because a request failed. No cleanup, database reset, dependency upgrade or application fix is implicit in these diagnostic steps.
